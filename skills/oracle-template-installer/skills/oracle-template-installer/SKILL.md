# 安装 Oracle 模板

以本文件所在目录为技能根。仅通过 `scripts/install.py` 的 `inspect`、`plan`、`apply`、`recover` 操作目标；该入口调用 `runtime.py` 完成运行时准备、兼容性验证及隔离注册。参数见[命令说明](references/cli.md)，发布范围见[版本与限制](references/release.md)。

1. **先检查。** 用 macOS 上的 Python 3.11+ 读取入口 `--help`，运行 `inspect`。先检查全局；已有项目根时另查项目。仅检查用户提供及客户端已知的技能路径。展示每个不同真实目录的候选、显示路径、范围、解释器和兼容结果；把同一真实目录的别名归为一个候选。未经探测的候选明确标为 `unprobed`，不能称为兼容。入口缺失、系统不支持或检查失败时报告具体阻碍。
2. **取得两个选择。** 分别取得“PPT Master 使用全局还是项目范围”和“Oracle 模板安装到全局还是项目范围”，并取得项目绝对路径。会话中已有明确选择时直接复用。缺少的选择各问一次，不从另一个选择推断。两个范围不一致时停止，在下载、建环境和目标写入前请用户对齐；有歧义时只澄清歧义。两个选择都为项目时，可在已有全局安装之外新建独立项目运行时。
3. **确定目标并计划。** 补查刚取得项目根的候选。有多个不同真实候选时由用户选择，不能凭发现顺序决定。用两个范围、项目根、选定运行时及对应解释器生成 `plan`。将 `--out` 放在私有 `--work` 内，并为后续执行和恢复保留同一工作目录。已有持久解释器绑定时沿用绑定，不依赖 shell 激活状态。项目入口解析到全局库时停止。读取计划 JSON；遇到 `blocked` 列出原因，兼容性失败不触发原地修补。
4. **审阅并执行。** 展示实际运行时、解释器、模板库和计划动作。新安装在用户明确给出两个范围选择后执行；相同目录且索引正确时保持 `keep`。存在冲突时，展示全部差异，包括将移除的用户文件、原索引、完整备份位置和计划摘要，并取得用户对这份具体计划的明确批准。批准前不执行 `apply`；批准后才传该计划的 `--confirm` 摘要。机器摘要只检测计划过期，本身不代表同意。现场或计划变化时重新计划，冲突重新批准。
5. **读取结果。** 用 `apply` 的 JSON 验证结果判断完成，不能仅凭退出码或文件存在。报告实际目标、两个范围、解释器、每种模板动作、验证结果、备份和回执路径。验证失败或证据缺失时报告阻碍，不宣称安装成功。全部 `keep` 时明确说明没有改写模板、索引或创建备份。

收到恢复请求或发现中断回执时，保留原回执与备份，按[恢复步骤](references/cli.md#恢复中断事务)调用 `recover`。恢复只处理仍符合事务前后像的对象；出现第三方内容时保留现场并报告阻碍。

不得执行载荷内或复制来源中的安装脚本，不直接运行真实库的上游注册器，不绕过 `runtime.py`。未知运行时必须通过完整性检查和实际隔离能力探测。所有测试使用独立 home、工作目录和模板目标。
